# MD工具箱 - 架构决策输入

> 状态：已确认  
> 决策角色：kimik3（临时代行）  
> 用途：供 deepseekv4pro 编写《架构设计文档》，供 glm5.2 在编码前确认技术边界。  
> 注意：本文是架构决策输入，不替代正式架构设计文档。

---

## 1. 决策目标

技术架构必须同时满足以下约束：

- Windows 10/11 x64 首发，核心功能完全离线可用。
- 冷启动目标小于 2 秒，空闲内存目标小于 200MB。
- 1MB Markdown 文档编辑到预览完成不超过 300ms。
- 支持 10 万行文本编辑，连续输入期间界面不阻塞。
- 安装包不超过 150MB，便携版不超过 200MB。
- 文件、编辑、渲染、主题、布局、导出和 AI 模块保持独立。
- AI 及其他 P2 能力不得增加 MVP 核心链路的耦合。

## 2. 技术选型

| 领域 | 选型 | 主要依赖 | 决策理由 |
|------|------|----------|----------|
| 桌面运行时 | Electron | `electron` | 与既定主进程/渲染进程目录一致，Node 文件能力及前端生态成熟 |
| 构建开发 | Vite + TypeScript | `vite`, `typescript` | 开发反馈快，支持 Worker、按需加载和严格类型检查 |
| UI 框架 | React | `react`, `react-dom` | 组件生态成熟，适合编辑器、预览区和多面板组合 |
| 编辑核心 | CodeMirror 6 | `@codemirror/*` | 模块化、扩展能力强，包体积和空闲内存低于 Monaco |
| Markdown 管线 | unified | `unified`, `remark-*`, `rehype-*` | AST 插件机制明确，便于扩展 GFM、公式、图表和锚点 |
| GFM | remark-gfm | `remark-gfm` | 提供表格、任务列表等标准扩展 |
| 公式 | KaTeX | `remark-math`, `rehype-katex`, `katex` | 渲染速度快，可离线打包字体和样式 |
| 代码高亮 | highlight.js | `rehype-highlight`, `highlight.js` | 支持按语言注册，避免完整语言包进入首屏 |
| 应用状态 | Zustand | `zustand` | API 简单，仅用于全局状态和用户偏好 |
| 模块事件 | 类型化事件总线 | `mitt` 或等价薄封装 | 用于一对多通知，不承担持久状态存储 |
| 运行时校验 | Zod + JSON Schema | `zod`, `ajv` | Zod 校验 IPC 边界，Ajv 校验可导入主题配置 |
| 单元/组件测试 | Vitest + Testing Library | `vitest`, `@testing-library/react` | 与 Vite/React 集成直接 |
| 集成/E2E | Playwright | `@playwright/test` | 可覆盖 Electron 核心用户流程 |
| 打包发布 | electron-builder | `electron-builder` | 支持 NSIS 安装包和 Windows portable 产物 |

依赖的确切版本由 glm5.2 创建脚手架时锁定，以当时稳定版本为准；不得使用浮动版本或在生产构建中引用 CDN。

## 3. 未采用方案

### 3.1 Tauri

一期不采用 Tauri。其安装体积更小，但会引入 Rust 工具链和额外跨语言边界，同时与现有 `src/main`、`src/renderer` 及 Electron 进程术语不一致。若 Electron 安装包无法满足 150MB 上限，再单独发起架构变更评估，不预留双运行时兼容层。

### 3.2 Monaco Editor

一期不采用 Monaco。MD工具箱以 Markdown 写作为主，CodeMirror 6 已覆盖语法高亮、撤销重做、查找替换和扩展快捷键，同时更有利于满足启动、内存和包体积指标。

### 3.3 MathJax

一期不采用 MathJax。KaTeX 的同步字符串渲染和较低运行成本更适合实时预览。公式引擎通过渲染模块内部适配接口隔离，后续可替换，但 MVP 不实现多引擎切换。

## 4. 进程与安全边界

应用划分为三个运行边界：

| 边界 | 职责 | 禁止事项 |
|------|------|----------|
| Electron 主进程 | 窗口生命周期、文件 I/O、原生菜单、系统对话框、日志与用户配置落盘 | 不解析 Markdown，不持有编辑器 UI 状态 |
| Preload | 将有限、类型化的 IPC 方法暴露给渲染进程 | 不暴露 `ipcRenderer`、`fs`、路径或任意通道调用能力 |
| 渲染进程 | React UI、CodeMirror、预览、主题、布局和交互状态 | 不启用 Node API，不直接访问文件系统 |

Electron 窗口必须采用以下基线：

- `contextIsolation: true`
- `nodeIntegration: false`
- `sandbox: true`
- 配置限制脚本和资源来源的 Content Security Policy。
- 外部链接交给系统浏览器打开，不在应用窗口内导航。
- IPC 请求和响应均校验载荷；文件路径只能来自系统对话框或已授权文档状态。
- 日志不得记录 API 密钥、文档正文或完整用户文件路径。

## 5. 模块边界

| 模块 | 所有权 | 对外能力 | 不应知道 |
|------|--------|----------|----------|
| 文件管理 | 主进程文件服务及渲染侧适配器 | 打开、保存、另存为、最近文件 | CodeMirror、Markdown AST、预览 DOM |
| 编辑核心 | CodeMirror 实例及编辑事务 | 读取/设置文本、订阅变更、聚焦、销毁 | 文件存储、Markdown 解析实现 |
| 渲染管线 | Markdown Worker、插件和预览提交 | 请求渲染、取消旧请求、返回结果 | 文件来源、编辑器实例、布局状态 |
| 主题引擎 | 主题定义、校验和 CSS 变量映射 | 加载、切换、查询、订阅主题 | 编辑内容、文件操作、Markdown AST |
| 布局管理 | 分屏比例、显示模式和面板状态 | 切换模式、调整比例、读取/恢复布局 | 文档内容、渲染实现 |
| 导出服务 | HTML/PDF 适配器 | 按格式导出已确认的文档快照 | 编辑器实例、布局组件 |
| AI 桥接层 | 后端配置、协议适配和流式响应 | 请求、取消、测试连接、管理配置 | CodeMirror 内部对象、预览 DOM |

每个模块通过自身 `index.ts` 暴露不超过 5 个核心接口。模块之间不得导入对方内部文件；共享类型只能向 `shared/` 单向依赖。

## 6. 核心数据流

正常编辑链路保持单向：

```text
文件服务 -> 文档状态 -> 编辑核心 -> 渲染调度器
        -> Markdown Worker -> 渲染结果 -> 预览视图
```

具体规则：

1. 打开文件后，主进程返回 UTF-8 文本和必要的文件元数据。
2. 文档状态将完整 Markdown 文本写入编辑核心。
3. 编辑事务产生文本快照、增量变化、光标位置和单调递增的修订号。
4. 渲染调度器防抖后向 Worker 发送文本快照和修订号。
5. Worker 返回 HTML、块锚点元数据、诊断信息和对应修订号。
6. 调度器只接收最新修订号的结果，过期结果直接丢弃。
7. 预览视图在替换内容前记录滚动锚点，提交后恢复阅读位置。

保存操作读取文档状态的当前文本快照，不从预览 HTML 反向生成 Markdown。

## 7. 渲染管线

MVP 管线采用以下阶段：

```text
Markdown 文本
  -> remark-parse
  -> remark-gfm
  -> remark-math
  -> 源位置与滚动锚点插件
  -> remark-rehype
  -> rehype-katex
  -> rehype-highlight
  -> rehype-sanitize（显式允许 KaTeX/高亮所需结构）
  -> HTML + 块锚点元数据
```

约束如下：

- MVP 不执行 Markdown 中的原始 HTML、脚本或内联事件。
- URL 协议只允许明确白名单，禁止 `javascript:` 等危险协议。
- KaTeX 失败时保留原始 LaTeX 文本并返回局部诊断，不中断整页。
- 代码语言包按需注册；未知语言按纯文本代码块输出。
- Mermaid 属于 P2 独立插件，不进入 MVP 首屏包。
- AST 只在渲染模块内存在，不通过事件总线或 Zustand 传播。

## 8. 状态与通信

状态按所有权拆分，禁止建立包含全部应用数据的单体 Store：

| 状态 | 所有者 |
|------|--------|
| Markdown 文本、选择区、撤销栈 | CodeMirror |
| 当前文件路径、脏状态、修订号 | 文档状态层 |
| 主题、布局、用户偏好 | Zustand 分片 |
| Markdown AST、渲染诊断 | 渲染管线 |
| 窗口及文件句柄 | Electron 主进程 |

事件总线只传递事实通知，例如：

- `editor:content-changed`
- `document:dirty-state-changed`
- `preview:render-completed`
- `preview:scroll-anchor-changed`
- `theme:switched`

同步查询和命令优先使用模块公开函数；一对多通知才使用事件总线。不得在事件载荷中传递 DOM、CodeMirror 实例、Electron 对象或 AST。

## 9. 性能策略

- Markdown 解析、公式和代码高亮在 Web Worker 中执行，避免阻塞输入线程。
- 输入防抖初始值设为 120ms，可根据性能测试调整，但总延迟不得超过 300ms。
- 每次渲染携带修订号；Worker 无需保证完成顺序，调用侧必须丢弃旧结果。
- CodeMirror 依赖自身视口虚拟化，不把全文同步复制到 React 组件状态。
- React 不按按键频率重建编辑器组件；状态栏使用独立订阅更新。
- 主题切换只更新 CSS 变量和编辑器主题扩展，不重新解析 Markdown。
- 首屏不加载 PDF、Mermaid、AI SDK及额外代码语言包。
- 性能测试必须分别记录输入响应、Worker 解析和 DOM 提交耗时，不能只记录总耗时。

若完整 DOM 替换无法满足 1MB 文档指标，优先在预览模块内部引入块级 keyed patch；不得为此改变模块公开接口。

## 10. 主题策略

- 主题源文件采用 JSON，并通过 JSON Schema 严格校验。
- 主题引擎将语义令牌映射为 CSS 变量，不允许组件硬编码主题颜色。
- P0 提供至少一套浅色和一套深色主题。
- P1 将浅色、深色主题分别扩展到至少两套并持久化用户选择。
- CodeMirror 使用主题适配器消费同一组语义令牌，避免维护两份颜色来源。
- 主题加载失败时回退到内置默认浅色主题，并显示非阻塞错误提示。

## 11. 打包与离线策略

- 使用 electron-builder 生成 Windows NSIS 安装包和 portable 版本。
- KaTeX 字体、样式、图标、主题和核心语言包全部随应用打包。
- 生产构建禁止 CDN 和运行时下载核心资源。
- 通过 Vite 分包延迟加载 P1/P2 能力，构建后检查产物体积和重复依赖。
- 安装数据与用户数据分离；用户偏好写入 Electron 用户数据目录。
- API 密钥不得写入仓库、日志或普通 JSON 配置；AI 阶段必须使用操作系统安全凭据能力或等价加密方案。

## 12. 测试与质量门槛

- Vitest 覆盖渲染插件、主题校验、修订号淘汰和滚动锚点纯逻辑。
- Testing Library 覆盖布局、状态栏和错误状态等组件交互。
- Playwright 覆盖打开、编辑、预览、保存、主题切换及离线运行。
- Electron IPC 必须包含成功、取消、非法载荷和文件失败测试。
- 依赖检查必须确认渲染进程无法直接访问 Node API。
- 1MB 文档、50 个以上公式和滚动位置保持属于合并前必测项。
