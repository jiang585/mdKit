## 1. 目录结构规范

```
md-toolbox/
├── docs/                       # 项目文档（本目录）
│   ├── 需求分析文档.md
│   ├── 架构设计文档.md
│   ├── 详细设计文档.md
│   ├── 项目路线图.md
│   ├── 开发规范.md
│   └── 测试报告.md
├── src/                        # 源代码
│   ├── main/                   # 主进程（文件 I/O、菜单、系统调用）
│   ├── renderer/               # 渲染进程
│   │   ├── editor/             # 编辑核心模块
│   │   ├── preview/            # 渲染管线模块
│   │   ├── theme/              # 主题引擎模块
│   │   ├── layout/             # 布局管理模块
│   │   ├── ai/                 # AI 桥接层模块
│   │   ├── export/             # 导出服务模块
│   │   ├── shared/             # 跨模块共享（类型定义、常量、工具函数）
│   │   └── App.tsx             # 根组件
│   └── assets/                 # 静态资源（字体、图标、内置主题文件）
├── tests/                      # 测试文件
│   ├── unit/                   # 单元测试
│   └── integration/            # 集成测试
├── .vscode/                    # VSCode 配置（共享）
│   ├── settings.json
│   └── extensions.json
├── .gitignore
├── README.md
├── package.json
├── tsconfig.json               # TypeScript 配置
├── .eslintrc.js                # ESLint 配置
└── .prettierrc                 # Prettier 配置
```

**约束**：
- 每个模块目录下最多嵌套两级子目录
- `shared/` 内禁止引用任何模块私有代码
- 模块私有代码不对外暴露，通过模块入口文件（`index.ts`）统一导出公开 API

## 2. 命名规范

| 类别 | 规范 | 示例 |
|------|------|------|
| 文件名 | 小写 + 连字符 / `index.ts` 入口 | `scroll-anchor.ts`, `markdown-parser.ts` |
| 组件文件 | PascalCase（React）/ 小写连字符（Vue） | `EditorPanel.tsx` |
| 类型/接口 | PascalCase，接口不加 `I` 前缀 | `MarkdownAST`, `ThemeConfig` |
| 变量/函数 | camelCase | `parseMarkdown()`, `currentTheme` |
| 常量 | UPPER_SNAKE_CASE | `MAX_RENDER_DELAY_MS` |
| 枚举成员 | PascalCase | `ThemeMode.Light` |
| 事件名 | 小写 + 冒号分隔命名空间 | `editor:content-changed`, `theme:switched` |
| CSS 类名 | 小写 + 连字符，模块前缀 | `md-editor-container`, `md-preview-code` |
| Git 分支 | 小写 + 斜杠分隔 | `feature/ai-bridge`, `fix/scroll-jump` |

## 3. Git 规范

### 3.1 分支模型

```
main               # 稳定发布分支
  └── develop      # 开发主线
       ├── feature/xxx   # 功能分支（从 develop 切出）
       ├── fix/xxx       # 修复分支（从 develop 切出）
       └── release/x.x.x # 发布分支（从 develop 切出）
```

### 3.2 提交信息格式

```
<type>(<scope>): <subject>

[body]

[footer]
```

| type | 含义 |
|------|------|
| `feat` | 新功能 |
| `fix` | Bug 修复 |
| `docs` | 文档变更 |
| `style` | 格式（不影响代码逻辑） |
| `refactor` | 重构（非功能、非修复） |
| `perf` | 性能优化 |
| `test` | 测试相关 |
| `chore` | 构建/工具/依赖变更 |
| `revert` | 回退提交 |

**示例**：
```
feat(editor): 添加 Markdown 语法高亮支持

基于 CodeMirror 6 的 markdown 语言包实现。
支持标题、粗斜体、列表、代码块的语法着色。

Closes #12
```

### 3.3 提交频率

- 每个逻辑单元一次提交
- 单次提交变更不超过 400 行（强制 Code Review 可行性）
- WIP 提交需以 `WIP:` 开头，合并前 squash

## 4. 模块通信规范

基于架构质量需求（高内聚 / 低耦合），模块间通信遵循以下约定：

### 4.1 通信方式优先级

| 优先级 | 方式 | 适用场景 |
|--------|------|----------|
| 1 | 函数调用（通过接口） | 编译时已知的同步调用 |
| 2 | 事件总线 | 一对多通知、模块间状态同步 |
| 3 | 回调注册 | 渲染结果回传等异步完成通知 |
| 4 | 全局状态 | 主题配置、用户偏好等全局共享数据 |

### 4.2 事件命名与载荷

事件名格式：`<模块>:<动作>[-<结果>]`

```typescript
// 示例：编辑核心发布内容变更
eventBus.emit('editor:content-changed', {
  source: 'user-input',       // 触发来源
  fullText: string,           // 完整文本
  delta: TextDelta,           // 增量变更
  cursorPosition: Position,   // 光标位置
});

// 预览模块触发滚动同步
eventBus.emit('preview:scroll-anchor-changed', {
  anchorId: string,           // 锚点 ID
  anchorType: 'heading' | 'paragraph',
});
```

### 4.3 禁止事项

- 禁止模块间直接引用对方的内部实现文件
- 禁止在事件载荷中传递 DOM 引用
- 禁止模块绕过入口文件直接 import 子模块私有代码
- 禁止循环依赖（CI 必须配置 `import/no-cycle` 规则）

## 5. 类型定义规范

### 5.1 模块公开接口

每个模块必须在入口文件（`index.ts`）中导出以下内容：

```typescript
// 模块类型定义
export interface EditorAPI {
  getContent(): string;
  setContent(text: string): void;
  on(event: EditorEvent, handler: Handler): void;
  off(event: EditorEvent, handler: Handler): void;
  destroy(): void;
}
```

### 5.2 数据模型约定

- 文档内容统一使用 `string` 类型传递（即 Markdown 源文本）
- AST 类中间产物为模块内部实现，不跨模块传递
- 主题配置使用严格的 JSON Schema 校验

## 6. 错误处理规范

| 场景 | 处理方式 |
|------|----------|
| 文件读取失败 | 用户可见的错误提示（Toast / 状态栏），不静默失败 |
| 渲染异常 | 隔离错误，仅影响报错节点，其余内容正常渲染；预览区显示错误占位符 |
| AI 请求失败 | 对话面板显示错误信息，重试按钮，不阻塞编辑器操作 |
| 未捕获异常 | 全局错误边界捕获，写入日志文件，提示用户重启 |
| 公式渲染失败 | 回退为原始 LaTeX 文本展示，不阻塞整页渲染 |
| 主题加载失败 | 回退到内置默认浅色主题，提示配置错误 |

## 7. 测试规范

### 7.1 测试分层

| 层级 | 覆盖目标 | 工具 | 覆盖率要求 |
|------|----------|------|------------|
| 单元测试 | 纯函数：MD 解析、公式渲染、消息处理 | Jest / Vitest | ≥ 80% |
| 组件测试 | UI 组件交互逻辑 | Testing Library | ≥ 60% |
| 集成测试 | 模块间通信、编辑→渲染链路 | Playwright | 核心路径 100% |
| E2E | 完整用户操作流程 | Playwright | 核心流程覆盖 |

### 7.2 测试文件命名

```
src/renderer/editor/syntax-highlight.ts
tests/unit/editor/syntax-highlight.test.ts     # 单测

tests/integration/edit-to-preview.spec.ts      # 集成测试
tests/e2e/create-and-save.spec.ts              # E2E
```

### 7.3 必测场景

- [ ] 空文档渲染不崩溃
- [ ] 1MB 大文件打开与编辑
- [ ] 50+ LaTeX 公式渲染
- [ ] 编辑后滚动位置保持不变
- [ ] 主题切换不丢失编辑内容
- [ ] AI Diff 接受 / 拒绝 / 撤销
- [ ] 断网时所有核心功能正常

## 8. 代码审查清单

每次 Code Review 必须检查以下条目：

- [ ] 新增代码有对应的单元测试
- [ ] 模块间通信只使用公开 API，无私有代码引用
- [ ] 没有引入循环依赖
- [ ] 错误路径有处理，不允许静默失败
- [ ] 新功能在对应优先级阶段内（参考路线图），未越级实现 P2 功能
- [ ] 无硬编码的魔法数字 / 字符串（提取为常量或配置）
- [ ] 日志输出不包含敏感信息（密钥、文件路径、用户内容）
- [ ] 性能关键路径（渲染、解析）避免不必要的重复计算

---

## 9. 文档规范

- 所有 `docs/` 下文档使用 Markdown 格式
- 文档变更与代码变更在同一次 PR 中提交（如有）
- Phase 阶段文档发布后，修订在下一阶段开始前冻结，新版覆盖旧版
- 架构/设计文档中的接口定义与实际代码同步维护，代码即文档的补充而非替代

---

## 10. 版本号规范

遵循语义化版本（SemVer）：

```
MAJOR.MINOR.PATCH

MAJOR: 不兼容的 API 变更或架构重写
MINOR: 向下兼容的新功能
PATCH: 向下兼容的 Bug 修复
```

阶段版本号约定：

| 阶段 | 版本号 | 说明 |
|------|--------|------|
| MVP | 0.x | 内部测试 |
| Phase 1~2 | 0.x | 功能迭代 |
| Phase 3 完成后 | 1.0.0 | 正式发布 |
