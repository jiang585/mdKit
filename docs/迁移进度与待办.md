## 🐞 预览/目录空白 bug —— 已修复 ✅

**根因**：React 18 StrictMode 在 dev 下双挂载组件。App 卸载时 `dispose()` 了渲染调度器，重挂载时 `ensureScheduler()` 发现 `schedulerRef.current` 非空就直接复用——已销毁的调度器内部 `if (disposed) return` 把后续所有渲染请求静默丢弃。编辑器走独立 ref 不受影响 → 「编辑区有内容、预览/TOC 永远空白」。

**为什么原版没暴露**：Electron 版 E2E 跑的是 build 产物（无 StrictMode 双挂载），单测全走 Mock，dev 模式下该 bug 潜伏未被发现。

**修复**（App.tsx 挂载 effect cleanup）：`schedulerRef.current?.dispose(); schedulerRef.current = null;`

**附带加固**（保留为永久韧性）：
- render.worker.ts：`renderMarkdown().catch()` → 回传 `worker-error`（消除静默失败）
- scheduler.ts：Worker 4s 无响应看门狗 → 自动降级主线程渲染；`worker-error`/加载失败 → 降级主线程
- 验证（隐形模式 + CLI 传文件，无头无窗口）：`runRender rev=1 len=83 → worker 渲染 htmlLen=1487 → 渲染交付 toc=1` 全链路打通
