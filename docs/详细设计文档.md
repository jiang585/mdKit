### 1.2 关键文件说明

| 文件 | 职责 | 约束 |
|------|------|------|
| `App.tsx` | 应用根组件：状态初始化、菜单命令路由、标签页生命周期、配置/主题/自动保存编排 | 不直接操作 CodeMirror AST |
| `main.tsx` | 渲染进程入口：React 挂载、全局错误边界、未捕获异常上报 | 最外层 |
| `bridge.ts` | `window.mdkit` 封装：Electron 优先，浏览器 Mock 降级 | 纯适配层，无业务逻辑 |
| `event-bus.ts` | 类型化事件总线：一对多通知，不承担持久状态 | 载荷不可包含 DOM/实例 |
| `document-store.ts` | Zustand 分片：标签页列表、激活状态、脏状态、路径绑定 | 不含编辑内容 |
| `autosave.ts` | 自动保存调度：按配置间隔保存 + 草稿定期落盘 | 依赖 bridge |

## 3. 状态管理与事件总线

### 3.1 状态所有权矩阵

| 状态数据 | 所有者 | 持久化 | 同步方式 |
|----------|--------|--------|----------|
| Markdown 文本 | CodeMirror 6 EditorState | 用户主动保存 | ref 读取 |
| 修订号 | App.tsx useRef | 否 | ref 读取 |
| 光标位置 | App.tsx useState | 否 | 事件推送 |
| 标签页列表 | Zustand (document-store) | 否 | 直接读取 |
| 标签页编辑器状态 | 内存 Map (tabStateStore) | 否 | 切换时 save/restore |
| 布局模式/比例 | Zustand (layout-store) | config.json | 直接读取 |
| 主题 | Zustand + CSS 变量 | config.json | 主题引擎内部 |
| AI 对话 | Zustand (ai-store) | 否 | 直接读取 |
| 用户配置 | 主进程 config-store | userData/config.json | IPC invoke |
| 草稿 | 主进程 drafts | userData/drafts/ | IPC invoke |

### 3.2 事件总线通道

```typescript
// event-bus.ts — 类型化事件映射
interface EventMap {
  'editor:content-changed':    { revision: number; source: EditSource };
  'document:dirty-state-changed': { tabId: string; dirty: boolean };
  'preview:render-completed':  { revision: number };
  'preview:scroll-anchor-changed': { line: number; type: 'heading' | 'block' };

```

订阅者异常隔离：单个 handler 抛出异常不影响其他订阅者（console.warn 记录后继续）。

## 4. 算法细节

### 4.1 滚动位置保持 (scroll-keeper.ts)

```
捕获阶段（innerHTML 替换前）:
  ① 计算当前 atBottom = scrollTop + viewportHeight ≥ contentHeight - 4
  ② 遍历所有 [data-md-line] 块，找到第一个底边越过视口顶沿的块
  ③ 记录 { line, offsetInBlock, rawScrollTop, atBottom }

恢复阶段（innerHTML 替换后）:
  ① 如果 atBottom → scrollTop = max(0, contentHeight - viewportHeight)
  ② 否则在新 DOM 中找行号最接近的块
  ③ target = block.top + min(offsetInBlock, block.height - 1)
  ④ scrollTop = clamp(target, 0, contentHeight - viewportHeight)
```

### 4.2 防抖渲染策略 (scheduler.ts)

```
request() → debounce(runRender, 120ms)

runRender():
  ① getSnapshot(): { markdown, revision, docPath }
  ② if revision ≤ delivered → return（已存在更新结果）
  ③ 构建 RenderRequest
  ④ 优先 Worker.postMessage()
  ⑤ Worker 不可用 → 动态 import 主线程管线
  ⑥ deliver():
    a. if revision ≤ delivered → return
    b. delivered = revision
    c. 回调 onResult
```

修订号淘汰（stale result rejection）：

```
Worker 不保证完成顺序
deliver() 只在 result.revision > delivered 时接受
后续接收旧修订号直接丢弃
```

### 4.3 光标同步 (cursor-sync.ts)

```
findAnchorLineForCursor(anchors, cursorLine):
  ① 二分查找 anchors 中 line ≤ cursorLine 且 endLine ≥ cursorLine
  ② 如果精确匹配 → 返回对应的锚点行
  ③ 否则取 cursorLine 前后最近的锚点行

PreviewPanel useEffect([cursorLine, syncCursor, result]):
  ① content.querySelector(`[data-md-line="${line}"]`)
  ② 添加 mk-cursor-sync 高亮 class
  ③ el.scrollIntoView({ block: 'nearest' })
```

### 4.4 自动保存 (autosave.ts)

```
createAutosave(getSnapshot):
  ① setInterval 按配置间隔触发
  ② 如果标签有路径 → IPC file:save（静默，无 Toast）
  ③ 无路径 → IPC draft:save（草稿，崩溃恢复用）
  ④ 每次保存后清空当前标签的草稿

autosave.dispose():
  ① clearInterval
  ② 立即保存当前标签 + 清除草稿
```

### 4.5 主题引擎 (engine.ts)

使用 Zod 内置主题校验（本次修复：原 Ajv 方式被 CSP 拦截）

```typescript
const colorSchema = z.string().regex(/^#[0-9a-fA-F]{3,8}$/);
const themeSchema = z.object({
  id: z.string().regex(/^[a-z0-9][a-z0-9-]{1,63}$/),
  name: z.string().min(1).max(64),
  kind: z.enum(['light', 'dark']),
  tokens: z.object(tokenShape).strict(),
  codeHighlight: z.object(highlightShape).strict().optional(),
}).strict();
```

主题应用流程：

```
applyThemes(registry, editorId, previewId):
  → registry.getOrFallback(editorId)  // 未知 id 回退 light-default
  → applyVars(root, editorScopeVars(editor.theme))
  → applyVars(root, previewScopeVars(preview.theme))
  → root.dataset.mkEditorTheme = theme.id
  → root.dataset.mkPreviewTheme = theme.id
  → root.dataset.mkKind = theme.kind
  → root.style.colorScheme = theme.kind
```

### 4.6 后处理插件 (post-process.ts)

```
walk(node, depth):
  if BLOCK_TAGS.has(tag) && depth ≤ 2:
    → 写入 data-md-line / data-md-line-end
    → 加入 anchors[]

  if HEADING_TAGS.has(tag):
    → 生成 id = `mdh-{startLine}`
    → 加入 toc[]

  if tag === 'img' && isRelativeSrc(src):
    → 有 docDir: src = `${DOC_ASSET_PROTOCOL}://local/?p=${encodeURI(abs)}`
    → 无 docDir: data-md-unresolved = true (预览占位)

  if tag === 'input':
    → disabled = true (任务列表只读)
```

### 4.7 AI Diff 算法 (diff.ts)

```
computeDiff(original: string, modified: string):
  ① 逐行拆分
  ② 使用最长公共子序列 (LCS) 算法
  ③ 生成 add/remove/keep 操作序列
  ④ 返回 AiDiff[] { type, fromLine, toLine, text, from? }

applyEdits(edits, source):
  ① 按 from 降序排序（从后往前应用，行号不变）
  ② dispatch 到 CodeMirror 6 事务
  ③ Ctrl+Z 可一步撤销全部 AI 写入（单事务包裹）
```

## 5. 错误处理约定

### 5.1 层级职责

| 层级 | 策略 |
|------|------|
| 主进程 IPC 校验 | Zod safeParse 失败 → 记录警告日志 → 抛 Error（渲染进程 catch） |
| 主进程文件操作 | try/catch → 抛 Error（渲染进程 catch → Toast 显示） |
| 渲染进程 API 调用 | try/catch → Toast 提示，不静默吞掉 |
| 渲染管线 | try/catch → 返回 `{ html: 占位, diagnostics: [...] }`，不抛异常 |
| 主题加载 | Zod safeParse 失败 → console.warn + 跳过，不中断主流程 |
| Worker 异常 | onerror → 主线程降级渲染，不中断预览 |
| 事件总线 handler | try/catch → console.warn + 继续执行其他订阅者 |
| React 组件 | ErrorBoundary 捕获 → 显示崩溃界面 + reload 按钮 |

### 5.2 统一错误上报

渲染进程未捕获异常通过 `bridge().log.rendererError()` 上报到主进程文件日志：

```typescript
// main.tsx
window.addEventListener('error', (event) => {
  bridge().log.rendererError(event.message, event.error?.stack);
});
window.addEventListener('unhandledrejection', (event) => {
  bridge().log.rendererError(`未处理的 Promise 拒绝：${reason?.message}`, reason?.stack);
});
```

主进程 `ErrorBoundary.componentDidCatch` 同样上报。

### 5.3 日志红线（不记录）

- API 密钥（`sk-...`、`key-...`、`Bearer ...` 等模式自动脱敏）
- 文档正文内容
- 完整用户文件路径（只保留文件名）

## 7. 渲染管线插件顺序

```
remark-parse
  → remark-gfm (singleTilde: false)
  → remark-math
  → remark-rehype (allowDangerousHtml: false)
  → rehype-sanitize (白名单方式放行 KaTeX/highlight.js 结构)
  → postProcessPlugin (data-md-line / TOC / 图片协议 / 复选框只读)
  → rehype-katex (errorColor, strict: 'ignore', throwOnError: false)
  → rehype-highlight (detect: false)
  → rehype-stringify
```

消毒白名单（sanitize-schema.ts）显式保留：
- `span.katex`, `span.katex-mathml`, `span.katex-html` 及子结构
- `math`, `mi`, `mo`, `mn`, `msup`, `msub` 等 MathML 标签
- `code`, `pre` 及 `hljs-*` class
- `img` 仅允许 `https:`, 自定义协议和 `data:` 路径
